双极眼电 EOG

预处理里有一步：把 3 个眼电通道标成 EOG，再算出双极眼电 HEOG = 左 − 右、VEOG = VEOG_lower − FP2。这一页说明眼电从哪来、为什么要两个电极相减，以及算出来以后拿来做什么。三张图都可以拖动。

1眼电通道在哪、记录什么

ERP CORE 的 N170 数据有 33 个通道：30 个头皮 EEG 通道，加 3 个眼电（EOG）通道 [1]。眼电通道不是用来研究大脑的，而是专门记录眼睛的动作。

通道位置记录什么
HEOG_left / HEOG_right左右眼的外眼角旁水平眼动（往左看、往右看）
VEOG_lower右眼下方眨眼、垂直眼动。和眼睛上方的头皮电极 FP2 配对使用
FP2额头上，右眼上方本身是头皮 EEG 通道，不是专门的眼电电极。因为正好在眼睛上方，会被借来和 VEOG_lower 配对，算双极 VEOG

需要它们，是因为眨眼和眼动产生的电信号比 EEG 大得多，会扩散到头皮上的电极，尤其是前额。

2眼睛本身就是一个偶极子

眼球前面的角膜相对后面的视网膜带正电，所以每只眼睛都像一个小电池，正极朝前。眼睛一转，正极就跟着转向某一侧，周围电极上的电压随之改变。

左侧电极（只算眼动）
右侧电极（只算眼动）
HEOG = 左 − 右

数值是示意，只表示方向和相对大小。

往左看时角膜（正极）靠近左边的电极：左边变正、右边变负。往右看正好反过来。两侧变化方向相反，所以左减右之后，眼动信号变成单侧的两倍，而且 HEOG 的正负直接告诉你眼睛往哪边转。

眨眼时眼皮滑过角膜，眼睛上方和下方的电极电压也是反方向变化（上方变正、下方变负），所以 VEOG 用"眼下 − 眼上"，眨眼会变成一个很大的负向尖峰。

3为什么要两个电极相减

单个眼电电极记录的是它相对于记录参考点的电压，里面除了眼动，还混着大脑活动和各种共同的噪声（比如 60 Hz 交流电、慢漂移）。这些成分在眼睛两侧的电极上几乎一样（毕竟两个眼睛是基本对称的）。设左右两个电极分别记录到：

左 = e + c　　　右 = −e + c　　　左 − 右 = 2e

e 是眼动在电极上造成的电压，c 是两侧共有的成分（大脑活动、共同噪声）。因为我们假设被试没有斗鸡眼，所以两个眼睛的眼动电压是一致的。相减后 c 消掉，e 变成两倍。

图 2 · 一段 2 秒的模拟眼电：往左看、眨眼、往右看
左侧 / 眼下电极右侧 / 眼上电极（FP2）双极：两者相减

把共同噪声调大，单个电极的波形很快就乱得看不出眼动；双极眼电几乎不受影响，0.5 秒的左看、1.0 秒的眨眼、1.4 秒的右看都清清楚楚。注意眨眼在 HEOG 上几乎看不到，在 VEOG 上很大；左右看则相反。两个双极眼电分工明确：

双极眼电怎么算主要看到方向
HEOGHEOG_left − HEOG_right左右眼动往左看为正，往右看为负
VEOGVEOG_lower − FP2眨眼、上下眼动眨眼是很大的负向尖峰

4算出来以后拿来做什么

主要用途是剔除 trial。如果刺激出现的那一刻被试正在眨眼或转眼睛，他可能根本没看清图片，眼电本身也会污染这段 EEG，这个 trial 就要删掉。ERP CORE 官方也是这么做的 [1]。做法很简单：在刺激呈现的时间段里，看双极 HEOG 和 VEOG 有没有超过阈值。

保留 / 剔除

阴影是刺激呈现的时间段（示意），红色虚线是阈值。在阴影里超过阈值的 trial 会被删掉；眨眼发生在阴影外面的 trial 保留。阈值调得太低会把正常的 trial 也删掉，太高又会放过真正的眨眼。ERP CORE 官方的阈值是逐个被试看数据定的，在这次练习中我们为了简化，用的是统一的阈值。

5为什么一定要在数据预处理的时候注意标记EOG类型？

数据读进 MNE 时，33 个通道默认都会被当成 EEG。把 3 个眼电通道标成 eog 之后，MNE 就知道它们不是大脑信号：做平均参考时，它们不会被算进所有电极的平均里；画头皮地形图时，它们不会出现；做 decoding 时，它们也不会被当成特征。

最后一点对 decoding 特别重要。被试看脸和看车时，眼睛的动法可能不一样，比如看脸时更常去看图里眼睛的位置。如果把眼电也放进特征里，分类器很可能靠眼动就把两类分开了，准确率看起来很高，其实和大脑没有关系。所以我们做 decoding 时只用 30 个头皮 EEG 通道。
