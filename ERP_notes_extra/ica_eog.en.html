ICA EOG Removal

(Translated by Claude Opus 5.5)

Trial rejection throws away the whole stretch of data that contains eye artifacts; ICA subtracts the eye artifacts from the data and keeps the trial. Section 1 explains what ICA is, Section 2 walks through each step in order, and Section 3 explains the principles.

1What ICA is

Every electrode on the scalp records a mixed signal: brain activity, blinks and eye movements stacked together in different proportions. For example, a blink is large at FP1 and FP2 and only a tiny bit is left at PO8 at the back of the head, but every electrode picks up some of it.

ICA assumes that at every moment, the voltage at each electrode is obtained by adding up a few mutually independent "components" in fixed proportions:

x = A s , x = xFP1⋮xPO8 , s = s1⋮sn
SymbolWhat it is
xThe voltage measured at each electrode at a given momentKnown; this is the only data we have
sThe strength of each component at the same moment. For example, the blink component is large during a blink and close to 0 otherwiseUnknown
AMixing matrix. Column j gives the proportion of component j at each electrode; drawn on the scalp, it is that component's topographic mapUnknown
WUnmixing matrix, equal to the inverse of A, satisfying s = W xUnknown

ICA computes W from x alone. Once we have W, we also have A (= W⁻¹) and s (= W x). Then we set the eye components to 0 and use x = A s to rebuild each electrode, which gives data without eye artifacts.

2What data each step uses and what it does

ICA goes after filtering and before epoching. Steps 1–4 are done on a copy, with the goal of computing W and A and picking out the eye components; steps 5–7 are done on the main data.

  1. CopyPrepare a copy

    Input
    Continuous data already filtered at 0.1–30 Hz
    Action
    Make a copy, apply a 1 Hz high-pass to the copy, then exclude segments with especially large amplitude, such as the participant moving around or coughing
    Output
    A copy used only for computing ICA. The main data stays unchanged

    Why 1 Hz → Principle ①

  2. CopyWhitening

    Input
    Data from the 30 scalp electrodes in the copy (EOG channels not used)
    Action
    Use PCA to turn the data from the 30 electrodes into a new set of signals that are mutually uncorrelated and all have variance 1. After average referencing, 30 electrodes can yield at most 29 such signals, so there are at most 29 components
    Output
    Whitened data z, and the whitening matrix (a record of how this transformation was done)

    What whitening is → see Principle ② first, then Principle ③

  3. CopyRotation

    Input
    Whitened data z
    Action
    Start from random directions and rotate a little at a time (gradient ascent) to find a set of directions such that, when the data are projected onto them, each resulting signal is "as non-normal as possible"
    Output
    W = rotation matrix × whitening matrix, A = W⁻¹. From these we get each component's time course (a row of s = W x) and topographic map (a column of A)

    The starting point is random, so you need to set random_state in the code to get the same result on every run.

    Why look for the "most non-normal" directions → Principle ④

  4. CopyIdentify the eye components

    Input
    Each component's time course and topographic map, plus the bipolar HEOG and VEOG in the copy. This is the first step where the EOG channels are used
    Action
    First use find_bads_eog to compute each component's correlation with HEOG and VEOG and take the highly correlated ones as candidates; then inspect the candidates' topographic maps and time courses yourself and confirm using the table below
    Output
    The indices of the components to remove, usually 1 to 3
    ComponentTopographic mapTime course
    BlinkConcentrated at the forehead, left–right symmetricLarge individual spikes, almost identical to VEOG
    Horizontal eye movementOn both sides of the forehead, positive on one side and negative on the otherStep-like jumps, almost identical to HEOG
    Brain activityMore spread out, often posterior or centralNo correspondence with the EOG

    Why not just use the EOG channels as the eye components → Principle ⑤; why you have to identify them yourself every time → Principle ⑥

  5. Main dataRemove the eye components

    Input
    The 0.1–30 Hz main data x, W and A from step 3, and the indices selected in step 4
    Action
    First compute s = W x, then set the selected components to 0, and finally use x = A s to rebuild each electrode
    Output
    Main data with the eye artifacts removed

  6. Main dataCheck the result

    Input
    The main data before and after correction
    Action
    Compare FP1 and FP2: the blink spikes should be gone. Compare PO8: the N170 should be essentially unchanged
    Output
    Confirmation that no brain component was removed by mistake. If the N170 is clearly smaller, go back to step 4 and check again

  7. Main dataEpoch and reject trials

    Input
    The corrected main data, plus the bipolar EOG before correction
    Action
    Epoch as usual and reject bad trials by threshold. To judge "was there a blink when the stimulus appeared", use the EOG from before correction
    Output
    Epochs ready for decoding

    After correction the blink can no longer be seen in the data, but the participant really did not see the image at that moment, so such trials still have to be removed [1].

3Principles

① Why compute on a 1 Hz copy but apply it to 0.1 Hz data

ICA assumes that each component's proportions across the electrodes are fixed, i.e. A in x = A s does not change over time. Slow drifts come from sweating and slowly changing electrode contact; their proportions across electrodes keep changing, which violates this assumption and degrades the decomposition. So they are removed with a 1 Hz high-pass before computing.

The resulting W and A only describe "how large a share each component has at each electrode". This share is determined by the positions of the eyes, the brain and the electrodes, and has nothing to do with which frequency band the data were filtered to. So W and A computed on the 1 Hz copy can be applied directly to the 0.1 Hz main data.

② First, how to read the scatter plot: one point is one moment

Principles ③ and ④ both use scatter plots, so here a minimal example shows how to read one. It uses the following two components and two electrodes.

The two components are blinks (occasional) and a 10 Hz α brain wave (always present); the two electrodes, picked at random, are FP2 and Pz. The two columns of the mixing matrix A that describe these two components are assumed to be:

Blink column = 10025 , α column = 1530

Plugging in: when the blink strength is 1, FP2 shows 100 μV and Pz shows 25 μV; when the α strength is 1, FP2 shows 15 μV and Pz shows 30 μV.

The scatter plot is drawn like this: at each moment FP2 has a value and Pz has a value; use these two values as the x and y coordinates and draw a point. Stack the points for every moment in 8 seconds and you get the cloud in the scatter plot in the figure on the right.

Click "Play" and watch how the point moves:

When there is no blink and only the α wave, FP2 and Pz move up and down slightly together with the α wave, and the point goes back and forth along one slanted line in the middle. When a blink happens, FP2 shoots up to about 100 and Pz rises to about 25, so the point dashes to the right along another line and comes back after the blink.

So the point cloud is made of two "arms". Tick "Show the two columns of A" to see: the direction of each arm is exactly one column of A. For ICA to compute A, it has to find the directions of these two arms.

Why does finding the arm directions let us separate them? Write x = A s out in terms of the two columns of A:

x = sblink 10025 + sα 1530

In other words, every point is reached by starting from where the two arms meet, moving sblink units along the blink arm and then sα units along the α arm. Once we know the directions of the two arms, we can read each point backwards as "how far along the blink arm and how far along the α arm"; these two numbers are the blink strength and α strength at that moment. Reading every moment this way gives two time courses, pure blink and pure α wave, and that is what "separating" means. After separating, set the blink one to 0 and rebuild, and the electrode data no longer contain the blinks.

③ Whitening: making the two arms perpendicular

In the raw data, the angle between the two arms is not 90° (about 49° at the start of Figure 2). Whitening has two steps:

Step one is straightening: find the direction in which the data are most spread out (the dashed line in Figure 2) and rotate the whole cloud so that this direction becomes horizontal; this step is PCA. Step two is scaling: stretch or compress the horizontal and vertical directions separately so that the variance in both directions equals 1.

Drag all the way to the right and the two arms become perpendicular. This is no coincidence: as long as the two components are independent, their directions are always perpendicular after whitening (the proof is not given here).

Why whiten first? Because after whitening there are fewer unknowns to find.

Before whitening, the angle between the two arms is unknown: here it is 49°, but it would be different for another dataset. So the direction of the blink arm and that of the α arm have to be found separately, 2 angles in total. After whitening, the two arms are always perpendicular; once you find one, the other lies perpendicular to it and needs no separate search, leaving only 1 angle.

Think of two clock hands. Before whitening, the two hands turn independently and you have to adjust two angles; after whitening, the two hands are welded into a right-angled cross, and turning a single angle lines both up with the two arms at once. The θ you drag in Figure 4 is this angle.

With 30 electrodes the reasoning is the same, just with bigger numbers. Before whitening, solving for W directly means determining 29 × 29 = 841 numbers. After whitening only a rotation remains: among the 29 coordinate axes, every pair of axes has one rotation angle, giving 29 × 28 ÷ 2 = 406 pairs, i.e. 406 angles, less than half of 841. And however you rotate, the data stay uncorrelated with variance 1, so these two conditions no longer need attention.

But whitening does not tell us which angle to turn the cross to: when Figure 2 is dragged all the way to the right, the two arms are still slanted relative to the axes. That is what step 3 is for.

Before getting to step 3, though, let us write the first two steps as a formula:

z = D−1/2 ET x

④ Rotation: how to know which angle to turn the cross to

First, back to the goal: we want to split each moment's electrode data into "how much blink, how much α wave", i.e. compute s, so that the blink part can be removed. Principle ② said that knowing the directions of the two arms is enough to separate them. After whitening the two arms are perpendicular and only one angle θ is unknown: turn a right-angled cross until it lines up with the two arms, and you have found the arm directions.

But the algorithm cannot see the arms. To judge whether the cross is aligned, it relies on the shape of the signals' histograms, so let us first get to know three kinds of histogram.

A histogram tallies up the values a signal takes over all moments: the horizontal axis is the value, and the taller the bar, the more often that value occurs.

A pure blink signal is 0 most of the time and occasionally very large, so its histogram is a sharp peak near 0 plus a long tail. A pure α wave is a sine, whose values mostly fall near the two extremes, so its histogram is high at both sides and low in the middle. Mix the two together and the histogram becomes closer to a bell shape, i.e. a normal distribution.

Try this: first click the three buttons to see the three shapes described above. With half blink and half α wave, k drops from 25.7 for pure blink to 6.1, already more bell-shaped than pure blink, but traces of the two sources are still visible. Then tick "Mix in 4 more independent signals": the histogram almost hugs the dashed bell curve and k drops to 0.7. The more independent signals mixed in, the closer to a bell shape.

The more you mix, the closer to a bell shape: this is the intuition behind the central limit theorem. Conversely, the less a signal's histogram looks like a bell, the more likely it is a "pure" signal that has not been mixed. Below we use this to find θ.

④ continued: turn the cross and find the least bell-shaped angle

What we are looking for by turning the cross is the angle that lines it up with the two arms. Once aligned, the two lines of the cross are the two arm directions, and each point's two coordinates on the cross are exactly what Principle ② called "how far along the blink arm and how far along the α arm", i.e. the separated s.

How to read it: treat the right-angled cross in the figure on the right as a new set of axes: the solid purple line is the y₁ axis and the dashed green line is the y₂ axis. Each point has two coordinates on these axes, which are the two outputs y₁ and y₂ at that moment. The large dot in the figure is the moment at 2.90 s (a blink is happening), and the two thin dashed lines mark its y₁ and y₂.

Read every moment this way, then connect all the y₁ values in time order and you get a new time course (the purple one at the lower right); the same goes for y₂ (the green one). So every angle the cross is turned to gives one way of separating: two new time courses.

Drag θ and watch these two time courses. When the cross is aligned with the two arms, one is pure blink and the other pure α wave, and the separation is correct; when it is not aligned, both curves contain a mix of blink and α wave.

We can tell whether the separation is right because we know what the true blink and α wave look like, but the algorithm does not. It can only look at the histograms of y₁ and y₂ themselves: when the separation is right, both outputs are pure signals, one histogram a sharp peak plus a long tail and the other high at both sides; when it is wrong, both outputs are mixtures and their histograms look more like a bell. So the angle that makes y₁ and y₂ least bell-shaped is the correct angle.

How "un-bell-like" something is gets measured with kurtosis:

k(y) = mean(y4) − 3 , J = |k(y1)| + |k(y2)|
SymbolWhat it is
yThe values of one output over all moments, already adjusted to mean 0 and variance 1
mean(y⁴)Each value raised to the fourth power, then averaged. Occasional large values become especially large after the fourth power, so the longer the tail, the larger this average. For a normal distribution it is exactly 3
k(y)Kurtosis. Normal distribution = 0; a long tail like a blink → a large positive number; a sine → −1.5
JSum of the absolute kurtoses of the two outputs. The larger J, the less bell-shaped the two outputs. Step 3 is exactly the search for the angle that maximises J

The curve at the upper right is J as a function of θ. Drag to the highest point of J and the cross lines up with the two arms; the histograms of y₁ and y₂ are one long-tailed and one high at both sides, and their similarity to the true components is close to 1. Drag to the lowest point and the cross sits exactly between the two arms; both outputs are mixtures and their histograms look more like a bell. Clicking "let the algorithm find it" is the gradient ascent of step 3: start from a random angle and each time turn a little in the direction in which J increases, until reaching the highest point.

In MNE, method can be fastica, infomax or picard. They use different formulas, and some do not use kurtosis, but the idea is the same: find the rotation that makes the outputs least like a normal distribution.

⑤ Why not just use the EOG channels as the eye components

The EOG channels are themselves mixed signals: the lower VEOG electrode and FP2 are both close to the frontal lobe and also record brain activity. If you subtract the EOG channel waveforms directly from each electrode (this is called the regression method, commonly used before ICA came along), you also subtract this part of the brain signal. ICA does not use the EOG channels in its computation and only uses them in step 4 to identify components.

⑥ Component order and sign carry no meaning

In Figure 4, every 90° turn of θ gives exactly the same J; the two outputs just swap places. In other words, ICA does not know the order of the components, so after every run you have to identify again which component is the eye artifact.

Also, multiplying a component by −1 while multiplying the corresponding column of A by −1 leaves x completely unchanged. So the sign of a component is arbitrary; the topographic maps in MNE may have red and blue flipped, and this does not affect the result.

4Why it is worth doing

The Luck lab used 15 datasets to test the effect of artifact handling on SVM decoding [2]. ICA correction did not consistently improve accuracy, but they still recommend using ICA to correct blinks and eye movements: if the eyes move differently when looking at faces and when looking at cars, the EOG itself can help the classifier separate the two classes and spuriously inflate accuracy. Only by correcting out the EOG can you be more confident that the classifier is using brain signals.
